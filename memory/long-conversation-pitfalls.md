## 长对话陷阱

### 问题
对话超过一定长度时：
1. **丢失状态跟踪** — 忘记之前读过什么文件、哪些操作已执行
2. **重复执行相同操作** — 重复读取/创建相同文件、执行相同命令
3. **死循环** — 操作失败时重复尝试相同操作，没有改变策略

### 根因
- 上下文窗口接近限制
- 没有检查返回结果（如 "Wasted call — file unchanged"）
- 没有记录已执行的操作

### 解决方案

1. **每次操作后检查返回结果**
   - "文件未改变" → 文件已在上下文中，不要重复读
   - 返回错误 → 改变策略，不要重复尝试

2. **用 task list 跟踪进度**
   - 避免忘记已执行的操作

3. **定期压缩对话**
   - 用 `/compact` 压缩，保留关键信息

4. **主动结束对话**
   - 上下文过长时建议用户结束，在新会话中重新开始

## Why:
长对话会导致资源浪费、效率下降、甚至死循环。

## How to apply:
长对话中定期检查返回结果，用 task list 跟踪，必要时建议用户结束对话。
