# 失败模式检测详细规则

> 借鉴 PUA 的 failure-detector.sh 模式分类逻辑，简化为 prompt 级行为约束。

## 错误签名提取

每次修复失败后，提取签名并记录在当前会话上下文中（不写文件）。

**签名格式**：`{错误类型}:{位置}:{关键特征}`

**示例**：

| 原始错误 | 签名 |
|---------|------|
| `NullReferenceException at OrderService.cs:42` | `NRE:OrderService:line42` |
| `Build error CS1061: 'IUser' has no 'Name'` | `CS1061:IUser:Name` |
| `Assert.Equal expected 3, got 2` | `AssertFail:TestX:count` |
| `TimeoutException in HttpClient.SendAsync` | `Timeout:HttpClient:SendAsync` |

**简化规则**：
- 只取错误类型（NRE / CS1061 / Timeout 等）
- 只取位置的文件名+行号或方法名
- 只取最关键的 1 个特征（缺失的成员、预期值等）
- 不需要精确哈希，人眼可判"相似"即可

## 模式分类标准

### SPINNING（原地打转）

**判定条件**：最近 3 次中有 2+ 次签名相同或高度相似。

**高度相似的定义**：
- 错误类型相同 + 位置相同（同一行/同一方法反复报错）
- 错误类型相同 + 特征相同（只是位置微调，本质问题没变）
- 例如：`NRE:OrderService:line42` 和 `NRE:OrderService:line45` → 高度相似

**强制动作**：
1. 禁止重试当前方法（包括参数微调、变量重命名、微小变体）
2. 列出 3 个**本质不同**的方案。"本质不同"要求：
   - 不同的算法/数据结构
   - 不同的库/框架
   - 不同的架构层（前端/后端/数据库/配置）
   - 不同的实现范式（命令式/声明式/事件驱动）
3. 评估每个方案的预期结果和风险
4. 选择最有把握的方案执行

### EXPLORING（探索收敛）

**判定条件**：最近 3 次签名全部不同，且错误类型或位置在逐步收窄。

**特征**：
- 每次错误都比上次更接近根因
- 错误从"泛化"变为"具体"
- 例如：`BuildError:whole_project` → `CS1061:IUser` → `CS1061:IUser:Name` → 收敛中

**强制动作**：
1. 保持当前方向，不要换方法
2. 为每个新错误标注"它告诉你什么"
3. 如果连续 2 次错误之间没有缩小范围 → 退化为 SPINNING

### MIXED（振荡）

**判定条件**：最近 3 次中，部分重复、部分新。在 2-3 个方案间来回切换。

**强制动作**：
1. 识别振荡的方案
2. 检查是否共享底层假设
3. 共享假设 → 假设可能错了，回到 Phase 1
4. 不共享 → 选最新失败的方向深入

## 伪切换检测

### 不算方案切换

- 换参数值（`timeout=30` → `timeout=60`）
- 换变量名（`data` → `result`）
- 换输出格式（`json` → `xml`，逻辑不变）
- 换错误处理方式（`try-catch` → `if-else`，触发条件不变）

### 算方案切换

- 换算法（冒泡排序 → 快速排序）
- 换库（Newtonsoft.Json → System.Text.Json）
- 换架构层（应用层修复 → 数据库层修复）
- 换实现范式（同步 → 异步）
- 换根本假设（"问题在 A" → "问题不在 A"）

### 检测方法

每次声称"换了方案"时，自问：
1. 新旧方案的**结构性差异**是什么？
2. 错误签名只是位置变了但类型没变 → 伪切换
3. 无法说出"这次用的是 [不同算法/不同库/不同层]" → 伪切换

## 方法论切换建议

连续失败需要换思路时，根据任务类型选择方向：

| 任务类型 | 无效方向 | 切换到 |
|---------|---------|-------|
| Debug | 从报错侧反复修 | 从调用侧追踪上游 |
| 功能实现 | "怎么实现 X" | "已有功能能否组合出 X" |
| 配置/部署 | 手动反复调参 | 自动化脚本或等效替代 |
| 性能优化 | 代码层微调 | 架构层（缓存/异步/批处理） |
| 依赖问题 | 降级/升级同一个依赖 | 换等价依赖或去掉依赖自己实现 |
