# 类型安全审计提示词

使用 review skill 的**类型安全模式**。

共享设置、覆盖度、报告模板、HTML 和 lint 规则在 `references/report-format.md` 中；在生成报告前加载该参考文件。

关注类型系统是否提供真实的安全保证或是否通过逃生舱口被绕过。

## 审查领域

### 不安全和逃生舱口
- `unsafe` 块 — 是否有正当理由？是否有安全注释？
- `any` / `unknown` 转换没有收窄。
- 类型断言（`as Type`、`as!`、`unchecked_cast`）— 是否可证明正确？
- 非空断言（`!`、`unwrap()`、`!!`）— 值是否真的可以为空？
- `// @ts-ignore` / `// @ts-expect-error` — 有多少，它们隐藏了什么？

### 输入边界弱点
- API 请求体类型为 `any` / `serde_json::Value` / `Dictionary`，没有验证。
- 配置文件解析没有模式验证。
- 外部数据直接转换为内部类型。
- 用户输入未验证就使用。

### 类型设计
- 类型过于宽泛
- 类型过于狭窄
- 类型不准确
- 类型不完整

### 类型使用
- 类型转换不当
- 类型比较不当
- 类型推断不当
- 类型断言不当
