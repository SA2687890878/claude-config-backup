# 后端 API 审计提示词

使用 review skill 的**后端API模式**。

共享设置、覆盖度、报告模板、HTML 和 lint 规则在 `references/report-format.md` 中；在生成报告前加载该参考文件。

关注 API 设计、请求/响应契约、数据访问模式和后端数据流一致性。

## 审查领域

### API 设计一致性
- 端点之间命名约定不一致（`/api/v1/users` vs `/api/getUsers`）。
- 混合响应格式（一些返回 `{data: ...}`，其他直接返回数组）。
- 状态码误用（错误返回 200，认证失败返回 400，验证返回 500）。
- 成功和错误返回不同形状的端点。
- 没有版本控制策略（或版本控制未实际执行）。

### 请求验证
- 端点边界缺少输入验证。
- 验证逻辑分散在处理程序中，而不是集中。
- 验证规则未记录。
- 验证错误消息不清晰。

### 响应格式
- 响应格式不一致
- 响应格式未文档化
- 响应格式难以扩展
- 响应格式难以解析

### 错误处理
- 错误响应格式不一致
- 错误码未定义
- 错误消息不清晰
- 错误未记录
