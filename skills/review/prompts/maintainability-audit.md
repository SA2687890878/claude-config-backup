# 可维护性审计提示词

使用 review skill 的**可维护性模式**。

共享设置、覆盖度、报告模板、HTML 和 lint 规则在 `references/report-format.md` 中；在生成报告前加载该参考文件。

关注可维护性、复杂度、耦合和设计风险。

## 审计维度

### 规模和结构（参见原则 1.1-1.6）
- 超过 500 行的文件
- 超过 50 行的函数
- 深层嵌套的函数（4+ 层）
- 职责过多的文件 — SRP 违规（原则 1.1）
- 边界不明确的模块

### 复杂度（参见原则 1.5-1.6）
- 圈复杂度热点（>10 条路径）
- 参数过多的函数（4+）— 原则 1.4
- 难以理解的控制流
- 难以测试的代码

### 耦合（参见原则 2.1-2.5）
- 依赖过多不稳定内部模块的模块
- 迪米特法则违规
- 高层业务逻辑中的具体基础设施依赖
- 紧耦合的模块

### 内聚（参见原则 2.1-2.5）
- 职责不相关的类/模块
- 数据和操作分离
- 过度分散的逻辑
- 过度集中的逻辑
