# 架构审计提示词

使用 review skill 的**架构模式**。

共享设置、覆盖度、报告模板、HTML 和 lint 规则在 `references/report-format.md` 中；在生成报告前加载该参考文件。

关注模块边界、依赖方向、分层、所有权以及系统形状是否支持安全变更。

## 审计维度

### 模块边界
- 所有权不明确或职责重叠的模块
- 领域逻辑分散在 UI、API 处理程序、数据库适配器和脚本中
- 隐藏不相关行为的"Utils"或"common"模块
- 公共 API 暴露实现细节
- 绕过预期边界的跨层导入

### 依赖方向
- 高层策略直接依赖低层基础设施
- 循环导入或包循环
- 不稳定的依赖被高层模块依赖
- 依赖方向不明确

### 分层
- 层之间没有明确边界
- 层之间直接调用，没有通过接口
- 层之间共享数据结构
- 层之间共享状态

### 所有权
- 数据所有权不明确
- 状态所有权不明确
- 资源所有权不明确
- 职责分配不明确
