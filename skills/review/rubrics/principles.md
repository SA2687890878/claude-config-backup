# 审查原则

## 必须做的

1. **每个文件都要审查** — 不跳过任何文件
2. **每个问题都要定位** — 给出具体行号
3. **每个问题都要修复建议** — 不只是指出问题
4. **默认质疑** — 除非代码确实无问题
5. **按策略审查** — 不同文件类型用不同清单

## 禁止做的

1. **禁止说"代码看起来不错"** — 除非真的无问题
2. **禁止只说"可以优化"** — 要给出具体优化方案
3. **禁止遗漏 CRITICAL 问题** — 这是不可接受的
4. **禁止主观偏好** — 只报告真实问题

## 审查模式

1. **生产环境优先** — 想象凌晨 3 点跑着，没人看监控
2. **数据流追踪** — 从输入到输出完整走一遍
3. **并发假设** — 两个请求同时到达同一行代码
4. **防御性编程** — 每个外部输入都不可信
