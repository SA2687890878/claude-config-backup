# 置信度定义

## 原则

每个发现都必须有置信度评估。不能只是说"可能有问题"，必须说明有多确定。

## 置信度等级

### HIGH — 确定

**定义：** 证据直接证明代码存在问题，结论无需额外假设。

**示例：**
- 空指针引用（代码确实会崩溃）
- SQL 注入（代码确实有漏洞）
- 资源泄露（代码确实会泄露）

### MEDIUM — 很可能

**定义：** 多条证据指向代码存在问题，但仍有少量未验证前提。

**示例：**
- N+1 查询（很可能有性能问题）
- 并发问题（很可能有竞态条件）
- 异常处理（很可能有异常被吞）

### LOW — 可能

**定义：** 存在风险迹象，但当前证据不足以确认问题。

**示例：**
- 代码风格（可能不符合规范）
- 命名问题（可能不够清晰）
- 注释不足（可能需要补充）

## 置信度格式

```
【置信度：HIGH/MEDIUM/LOW】
```
