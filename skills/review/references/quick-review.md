# 快速审查详细流程

## 适用场景

- 只改了几行代码（< 50 行 diff）
- 不需要完整审查流程
- 只需要快速给意见

## 输出格式

一行一个发现，带严重级别标签，直接可贴到 PR 评论。

```
L42: 🔴 bug: null 检查缺失，.find() 后可能为 null。加守卫。
L88: 🔵 nit: 50 行函数做了 4 件事。拆分为 validate/normalize/persist。
L23: 🟡 risk: 429 未重试。用 withBackoff(3) 包装。
```

## 严重级别标签

- `🔴 bug:` — 破坏性行为，会导致事故
- `🟡 risk:` — 能跑但脆弱（竞态、缺少 null 检查、吞异常）
- `🔵 nit:` — 风格、命名、微优化，作者可忽略
- `❓ q:` — 真正的问题，不是建议

## 规则

- 位置 → 问题 → 修复，三个要素缺一不可
- 禁止客套（"我注意到..."、"你可能想..."）
- 禁止复述代码做了什么（审查者能看 diff）
- 不确定就用 `❓ q:` 而不是猜测
- 安全漏洞（CVE 级别）自动切换回完整审查模式

## 示例

```
L15: 🔴 bug: SQL 注入风险，直接拼接用户输入。用参数化查询。
L32: 🟡 risk: 异步方法调用 .Result，会阻塞线程。用 await。
L45: 🔵 nit: 变量名 temp 不清晰。改为 validationResult。
L67: ❓ q: 这里的 null 检查是否足够？.FirstOrDefault() 后可能为 null。
```
