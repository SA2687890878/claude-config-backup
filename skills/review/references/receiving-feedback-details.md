# 接收审查反馈详细流程

技术评估，不是情绪表演。Read 工具读出乱码时，用 PowerShell `[System.IO.File]::ReadAllText('路径', [System.Text.Encoding]::UTF8)` 读取。

## 响应模式

1. **READ**: 完整读完反馈，不反应
2. **UNDERSTAND**: 用自己的话复述需求（或提问）
3. **VERIFY**: 对照代码库实际验证
4. **EVALUATE**: 对这个代码库技术上合理吗？
5. **RESPOND**: 技术确认或有理有据的 push back
6. **IMPLEMENT**: 逐项修复，每项测试

## 详细流程

### 1. READ — 完整读完反馈

- 不要中断
- 不要反应
- 不要反驳
- 不要解释

### 2. UNDERSTAND — 理解反馈

- 用自己的话复述
- 确认理解正确
- 如有疑问，提问

### 3. VERIFY — 验证反馈

- 对照代码库验证
- 检查是否真的有问题
- 检查是否有上下文

### 4. EVALUATE — 评估反馈

- 技术上是否正确？
- 是否适用于这个代码库？
- 是否有更好的解决方案？
- 是否值得实施？

### 5. RESPOND — 响应反馈

- 技术确认
- 有理有据的 push back
- 提供替代方案

### 6. IMPLEMENT — 实施修复

- 逐项修复
- 每项测试
- 验证修复
