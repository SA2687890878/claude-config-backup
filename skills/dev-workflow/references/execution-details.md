# 执行计划详细流程

## 加载并审查

读取计划文件 → 批判性审查 → 有问题在开始前提出 → 没问题创建任务列表（DSH: `todo_write` / Claude: `TodoWrite`）继续。

## 执行 Tasks

逐 task：标记 in_progress → 严格按步骤执行 → 运行验证 → 标记 completed。

**连续执行：** 不要在 task 之间暂停。只有 BLOCKED、歧义、或全部完成才停下。

## 每阶段验证

每个 task 完成后，**必须**执行以下检查再进入下一个 task：

1. **验证子任务**：运行计划中定义的验证步骤（测试、grep 检查等）
2. **反模式扫描**：grep 检查已知的坏模式（如 `.Result`、空 catch、硬编码密钥）
3. **代码质量快查**：检查本次变更是否引入新问题
4. **通过才提交**：验证不通过则修复后再继续，不跳过

**核心原则：** 宁可每步多花 1 分钟验证，不要到最后才发现前 3 步全错了。

## 停下求助

碰到阻塞（缺失依赖、测试失败、指令不清）立即停下。宁可问也不要猜。

## Subagent 模式

对每个 task 派 fresh subagent + 两阶段 review。

**连续执行：** 不要在 task 之间暂停检查用户。只有 BLOCKED 无法解决、歧义阻止进展、或全部完成才停下。

## 模型选择

| 任务类型 | 模型 |
|---------|------|
| 机械实现（1-2 文件，清晰 spec） | 快速模型 |
| 集成和判断任务（多文件协调） | 标准模型 |
| 架构、设计、审查 | 最强模型 |
