# 代码审查工作流

## 代码探索铁律

审查需要达到上下文时先用索引、最后才 Read。遵循 [`rules/tools/code-access.md`](../../rules/tools/code-access.md) 的决策树。

## 路由

| 意图 | 分支 |
|------|------|
| 审查代码变更（"帮我看看"、"review"、"审查"） | → A. 执行审查 |
| 快速审查（"快速看看"、"quick review"、"这几行有问题吗"） | → E. 快速审查 |
| 请求 subagent 审查（"请求审查"、"让别人看看"） | → B. 请求审查 |
| 接收审查反馈（"收到反馈"、"reviewer 说"） | → C. 接收反馈 |
| 不确定 | → A. 执行审查（默认） |

---

## A. 执行审查

**核心流程：**
1. 确定范围：`git diff` 获取变更
2. 智能选择审查维度（见下方"按变更类型选择维度"）
3. 执行审查：读取 `references/checklist.md`，按分类逐项检查
4. 输出报告：读取 `references/report-template.md`

**按变更类型选择维度：**

不是每次都需要跑完整 checklist。根据变更内容自动选择：

| 变更文件类型 | 重点审查维度 |
|-------------|------------|
| `*Controller*.cs` | 认证授权、输入验证、错误处理 |
| `*Service*.cs` / `Achieved/*.cs` | 业务逻辑、事务边界、异常处理 |
| `*DbContext*.cs` / `ModelMap/*.cs` | EF Core 查询安全、N+1、事务 |
| `Model/*.cs` | 类型安全、可空注解、序列化 |
| `*Filter*.cs` | 认证逻辑、异常捕获 |
| `*.json` / `*.xml` | 配置安全、敏感信息泄露 |
| 测试文件 | 测试覆盖、断言质量 |
| 多个文件跨层 | 架构一致性、依赖方向 |

**严重级别：**
- **CRITICAL** — 生产必炸（数据丢失、安全漏洞、死锁）
- **HIGH** — 很可能出问题（未处理异常、资源泄漏）
- **MEDIUM** — 可能出问题（边界条件、性能隐患）
- **LOW** — 代码质量（命名、冗余、可读性）

**认知模式：**
1. 生产环境优先 — 想象凌晨 3 点跑着，没人看监控
2. 数据流追踪 — 从输入到输出完整走一遍
3. 并发假设 — 两个请求同时到达同一行代码
4. 防御性编程 — 每个外部输入都不可信

## E. 快速审查

**适用场景：** 只改了几行代码，不需要完整审查流程，只需要快速给意见。

**格式：** 一行一个发现，带严重级别标签，直接可贴到 PR 评论。

```
L42: 🔴 bug: null 检查缺失，.find() 后可能为 null。加守卫。
L88: 🔵 nit: 50 行函数做了 4 件事。拆分为 validate/normalize/persist。
L23: 🟡 risk: 429 未重试。用 withBackoff(3) 包装。
```

**严重级别标签：**
- `🔴 bug:` — 破坏性行为，会导致事故
- `🟡 risk:` — 能跑但脆弱（竞态、缺少 null 检查、吞异常）
- `🔵 nit:` — 风格、命名、微优化，作者可忽略
- `❓ q:` — 真正的问题，不是建议

**规则：**
- 位置 → 问题 → 修复，三个要素缺一不可
- 禁止客套（"我注意到..."、"你可能想..."）
- 禁止复述代码做了什么（审查者能看 diff）
- 不确定就用 `❓ q:` 而不是猜测
- 安全漏洞（CVE 级别）自动切换回完整审查模式

读取 `references/quick-review.md` 了解完整格式和示例。

## B. 请求审查

读取 `references/request-review.md`，按步骤派发 code reviewer subagent。

核心流程：获取 git SHAs → 构造审查上下文 → 派发 subagent → 按严重级别处理反馈。

---

## C. 接收反馈

技术评估，不是情绪表演。

**响应模式：**
1. READ: 完整读完反馈，不反应
2. UNDERSTAND: 用自己的话复述需求（或提问）
3. VERIFY: 对照代码库实际验证
4. EVALUATE: 对这个代码库技术上合理吗？
5. RESPOND: 技术确认或有理有据的 push back
6. IMPLEMENT: 逐项修复，每项测试

读取 `references/receiving-feedback-details.md` 了解完整流程。
