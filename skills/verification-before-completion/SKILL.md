# 验证优先

## 核心铁律

**没有新鲜的验证证据，不许宣称完成。**

## 验证流程

在声称任何状态或表达满意之前：

1. **识别** — 什么命令能证明这个结论？
2. **运行** — 执行完整命令（新鲜、完整）
3. **读取** — 完整输出，检查退出码，计数失败
4. **验证** — 输出是否确认结论？
   - 否 → 陈述实际状态和证据
   - 是 → 带着证据陈述结论
5. **然后** — 才能下结论

跳过任何一步 = 说谎，不是验证。

## 常见验证要求

| 结论 | 需要 | 不够 |
|------|------|------|
| 测试通过 | 测试命令输出：0 失败 | 之前的运行、"应该通过" |
| Linter 干净 | Linter 输出：0 错误 | 部分检查、推断 |
| 构建成功 | 构建命令：exit 0 | Linter 通过、日志看起来好 |
| Bug 修复 | 测试原始症状：通过 | 改了代码、假设修好了 |
| 需求满足 | 逐条检查清单 | 测试通过 |
| Agent 完成 | VCS diff 显示变更 | Agent 报告"成功" |

## 红旗 — 停下

- 用"应该"、"可能"、"看起来"
- 验证前表达满意（"完美！"、"搞定了！"）
- 即将 commit/push/PR 但没验证
- 信任 agent 的成功报告
- 依赖部分验证
- 想"就这一次"

## 防合理化

| 借口 | 现实 |
|------|------|
| "应该没问题了" | 去跑验证 |
| "我有信心" | 信心 ≠ 证据 |
| "就这一次" | 没有例外 |
| "Linter 过了" | Linter ≠ 编译器 |
| "Agent 说成功了" | 独立验证 |
| "我累了" | 疲劳 ≠ 借口 |
| "部分检查够了" | 部分证明不了什么 |

## 底线

**验证没有捷径。** 跑命令。读输出。然后下结论。没有商量余地。
