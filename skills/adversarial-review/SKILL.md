# Adversarial Review — 独立对抗性审查

## 核心理念

**默认代码有问题，除非你能证明它没问题。**

你的任务是找出代码中的所有问题。不是"代码看起来不错"，而是"这里有个 bug"。

## 触发条件

- 用户说"审查代码"、"review"、"帮我看看"、"找找 bug"
- Claude 完成任务后，hook 自动提醒
- 修改代码文件后

## 审查流程

### 第一步：收集变更

```bash
# 获取本次修改的文件（优先用 git diff）
git diff --name-only HEAD

# 或获取未提交的修改
git diff --name-only

# 如果不是 git 仓库，用 glob 查找最近修改的文件
```

### 第二步：分析变更类型，选择审查策略

**根据文件扩展名自动选择**：

| 文件类型 | 审查策略 | 审查重点 |
|----------|---------|---------|
| `.cs` | C# 审查 | 空指针、资源泄露、异步问题、SQL 注入 |
| `.vue` | Vue 审查 | v-for key、computed 副作用、XSS |
| `.js` / `.ts` | JS/TS 审查 | 类型安全、异步处理、内存泄露 |
| `.sql` | SQL 审查 | 注入风险、性能、索引 |
| `appsettings*.json` | 配置审查 | 密钥泄露、敏感信息 |
| `.csproj` | 依赖审查 | 已知漏洞、版本过旧 |
| `.env` / `*.env.*` | 环境变量审查 | 密钥暴露 |

### 第三步：派 agent 执行审查

**关键设计**：使用 Agent 工具派独立 agent，而不是自己审查自己。

```
Agent 提示词模板：

你是代码审查专家，专门找问题。

审查目标：[文件列表]
审查策略：[选择的策略]

规则：
1. 默认代码有问题，除非你能证明它没问题
2. 每个问题都要给出具体行号
3. 每个问题都要给出修复建议
4. 不要说"代码看起来不错"，除非真的无问题

使用 [对应的 checklist] 作为审查清单。
```

### 第四步：汇总去重

- 多个 agent 的发现可能重复
- 按文件+行号去重
- 保留最严重级别

### 第五步：输出报告

严格格式：

```
## 对抗性审查报告

### 变更概览
- 文件数：X 个
- 变更类型：C# / Vue / SQL / 配置

### CRITICAL
- [文件:行号] 问题描述 → 修复建议

### HIGH
- [文件:行号] 问题描述 → 修复建议

### MEDIUM
- [文件:行号] 问题描述 → 修复建议

### 统计
- CRITICAL: X 个
- HIGH: X 个
- MEDIUM: X 个
- LOW: X 个

### 建议
- 必须修复：[CRITICAL + HIGH 列表]
- 建议修复：[MEDIUM 列表]
```

## 审查策略详情

### 策略 1：C# 审查

**审查清单**：[references/dotnet-checklist.md](references/dotnet-checklist.md)

**认知模式**：
1. **生产环境优先** — 并发访问、大数据量、异常情况
2. **数据流追踪** — 数据从哪来、到哪去、中间处理
3. **防御性编程** — 输入合法性、外部依赖可用性

**重点关注**：
- 空指针引用（Find/FirstOrDefault 后未检查 null）
- 资源泄露（IDisposable 未 using）
- 异步阻塞（.Result/.Wait()）
- SQL 注入（字符串拼接 SQL）
- 并发死锁（共享状态无锁保护）

### 策略 2：Vue 审查

**审查清单**：[references/vue-checklist.md](references/vue-checklist.md)

**重点关注**：
- v-for 缺少 :key
- computed 中有副作用
- 事件监听未在 beforeDestroy 移除
- XSS 风险（v-html、用户输入）
- 大列表未使用虚拟滚动

### 策略 3：SQL 审查

**审查清单**：[references/sql-checklist.md](references/sql-checklist.md)

**重点关注**：
- SQL 注入（字符串拼接）
- 全表扫描（缺少 WHERE、缺少索引）
- N+1 查询
- 事务边界

### 策略 4：配置审查

**审查清单**：[references/config-checklist.md](references/config-checklist.md)

**重点关注**：
- 密钥硬编码
- 敏感信息暴露
- CORS 配置过宽
- 调试模式未关闭

## 审查原则

### 必须做的

1. **每个文件都要审查** — 不跳过任何文件
2. **每个问题都要定位** — 给出具体行号
3. **每个问题都要修复建议** — 不只是指出问题
4. **默认质疑** — 除非代码确实无问题
5. **按策略审查** — 不同文件类型用不同清单

### 禁止做的

1. **禁止说"代码看起来不错"** — 除非真的无问题
2. **禁止只说"可以优化"** — 要给出具体优化方案
3. **禁止遗漏 CRITICAL 问题** — 这是不可接受的
4. **禁止主观偏好** — 只报告真实问题
5. **禁止只审查 .cs 文件** — 所有变更文件都要审查
