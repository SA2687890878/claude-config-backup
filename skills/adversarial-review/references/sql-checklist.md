# SQL 代码审查清单

## CRITICAL — 生产必炸

### SQL 注入
- [ ] 是否使用参数化查询
- [ ] 是否有字符串拼接 SQL
- [ ] 动态表名/列名是否安全（白名单验证）
- [ ] 存储过程是否有注入风险

### 数据丢失
- [ ] DELETE/TRUNCATE 是否有 WHERE 条件
- [ ] UPDATE 是否有 WHERE 条件
- [ ] DROP TABLE/DATABASE 是否必要
- [ ] 是否有事务保护

## HIGH — 很可能出问题

### 性能问题
- [ ] 是否有全表扫描（缺少 WHERE、缺少索引）
- [ ] 是否有 SELECT *（只查需要的列）
- [ ] 大表查询是否有分页
- [ ] 聚合查询是否在大表上做全表扫描
- [ ] OR 条件是否导致全表扫描（考虑 UNION）

### 索引问题
- [ ] WHERE 条件字段是否有索引
- [ ] JOIN 条件字段是否有索引
- [ ] ORDER BY 字段是否有索引
- [ ] 外键字段是否有索引
- [ ] 索引是否过多（影响写入性能）

### 并发问题
- [ ] 是否有死锁风险（多个事务顺序不一致）
- [ ] 锁粒度是否合适（行锁 vs 表锁）
- [ ] 长事务是否持有锁过久

## MEDIUM — 可能出问题

### 数据完整性
- [ ] 外键约束是否正确
- [ ] NOT NULL 约束是否正确
- [ ] 唯一约束是否正确
- [ ] 默认值是否合理

### 数据类型
- [ ] 字段类型是否合适（varchar 长度、int 范围）
- [ ] 时间字段是否用 timestamp with time zone
- [ ] 枚举值用 integer 或 text，不用自定义 type

### 查询逻辑
- [ ] JOIN 类型是否正确（INNER vs LEFT）
- [ ] 子查询是否可以改为 JOIN
- [ ] UNION 是否去重（UNION ALL 是否必要）
- [ ] GROUP BY 是否正确（SELECT 字段是否都在 GROUP BY 中）

## LOW — 代码质量

- [ ] SQL 格式是否清晰
- [ ] 表名/列名是否有注释
- [ ] 复杂查询是否有说明
- [ ] 存储过程是否有文档
