# 三花/PCS 发布约束

## 分支与流程

- 常见分支：`develop`、`test`、`feature_*`；以实际仓库保护策略为准。
- 功能在 `feature_*` 开发并提交；需要测试时合入 `test`，构建/打包到测试环境并完成功能测试。
- 测试失败返回开发阶段修复；测试通过后进入发布流程。
- 发布前按组织流程申请发布；必要时先同步 `develop` 到功能分支，解决冲突，再发起 `feature_* → develop` 合并请求。
- 代码审核通过后完成合并；不直接推送受保护分支。

## 发布检查

- 确认代码审查、测试证据、配置、数据库变更、日志/监控和回滚步骤。
- 发布包清理无用代码、配置和依赖；环境配置不得硬切换。
- 具体审批角色、窗口、分支保护和部署命令以当前仓库/组织流程为准。
