# PCS 日志约束

## 模块和链路

- 模块分类：`SYS`、`BIZ`、`SDK`、`DEV`。
- 业务入口创建调用链 ID；BIZ、SDK、DEV 继承；SYS 只记录关键系统事件，不强制带业务链路。
- .NET 异步调用链优先通过异步上下文隐式传递（如 `AsyncLocal`）；并发业务之间必须隔离，不把 ID 机械加入每个方法参数。
- 调用链 ID 用于检索一次工单/设备业务的全链路日志；无上下文时允许降级，但不得伪造关联关系。

## 系统启动

- 初始化按 `[N/M]` 记录关键步骤，至少覆盖版本、配置、设备连接、数据库连接和系统就绪。
- 初始化失败记录失败步骤和原因；关闭记录关键结果。
- 非初始化事件不强制使用步骤编号。

## 业务链路

典型链路：

```text
工单接收 → 条码生成 → 获取待打印数据 → 下发标刻指令
→ 设备反馈 → 扫描校验 → 条码状态回写 → DAQ 数据保存 → 工单汇总
```

- BIZ 记录关键节点、步骤、结果和耗时；工单结束记录成功数、总数和总耗时。
- SDK/DEV 日志必须能回答：调用/交互对象、结果、错误码或原因、耗时、所属调用链。
- 业务成功但设备、回写或保存失败时，分别记录边界结果，不得只记录最终成功。

## SDK 交互

- 成功：记录方法、关键结果字段、耗时和安全的输入摘要。
- 失败：记录方法、失败原因/错误码、耗时、安全的输入和输出摘要。
- 默认不记录完整 JSON；原始数据仅在必要时按白名单、脱敏和长度限制记录。

## 设备交互

- 设备发送使用 `[TX]`，反馈使用 `[RX]`，必要时附安全摘要。
- 轮询状态未变化时不重复输出普通日志；状态变化记录旧值、新值、原因、时间和调用链。
- 设备离线、超时、未知状态、异常反馈必须记录；不能因降噪丢失故障事件。

## 远程与本地兜底

- 远程日志失败不得阻塞业务；必须有超时和降级路径。
- 关键日志在远程不可用时保留本地兜底，避免配置拉取失败时无日志可查。
- Logger 重建前释放旧实例；退出时 flush；本地日志按天轮转并限制保留和磁盘增长。
- 运行日志、审计日志、调试日志分别定义保留周期；具体天数以项目合规和运维策略为准。

## PCS 约定

- 远程日志配置类别、Stream 和业务上下文字段以项目实际配置为准；不复制凭据。
- 常见约定为 `PCSLog`、`{com_id}_{act_name}` 和业务上下文，但使用前必须核对代码与配置。
