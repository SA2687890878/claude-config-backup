# 代码审查清单（统一标准）

> 所有代码审查（agent、workflow、skill）引用此文件，不重复定义。

## 审查维度

### 1. 正确性
- 逻辑是否正确
- 边界条件是否处理
- 异常处理是否完善
- 资源是否正确释放

### 2. 安全性
- SQL 注入风险（参数化查询）
- XSS 漏洞（用户输入转义）
- 硬编码密钥/密码
- 权限校验
- 敏感数据日志

### 3. 性能
- N+1 查询（Include/Join 替代循环查询）
- 不必要的数据库调用
- 大对象分配
- 同步阻塞（.Result/.Wait()）
- 缺少索引

### 4. 可维护性
- 命名是否清晰
- 方法长度是否合理
- 单一职责原则
- 重复代码

### 5. 多租户
- ComId 是否正确处理
- 数据隔离是否正确

### 6. 外部边界与可观测性
- HTTP、数据库、SDK、消息或设备调用是否有超时、取消和失败处理
- 重试、降级和幂等是否与业务语义匹配
- 日志是否包含必要的结果、错误码、耗时和关联 ID
- 日志输入输出是否按白名单记录并脱敏，是否限制超长报文
- 配置、版本兼容和资源释放是否符合项目约束

### 7. 业务完整性
- 是否覆盖空数据、异常数据、重复提交、权限拒绝和状态竞态
- 数据库更新是否避免无依据的先删后插，迁移是否有回滚/兼容策略

## 审查纪律

- **只报真实问题**：不要为"凑数"制造发现
- **不报风格偏好**：除非违反项目约定
- **不报理论问题**：只报实际会影响正确性/安全的问题
- **修复正确就判 PASS**：不要因为"被要求找问题"而过度报告
- **独立复核**：验收者必须独立重读真实文件与运行结果，不回采实施者自报的 `passed` / 构建成功 / 截图结论
- **验收矩阵**：对用户可见操作记录 动作 / 操作前状态 / 操作后状态 / 证据 / 结论，核心路径无证据不得 PASS

## 严重级别

| 级别 | 定义 | 处理 |
|------|------|------|
| CRITICAL | 生产必炸 | 必须修复 |
| HIGH | 很可能出问题 | 强烈建议修复 |
| MEDIUM | 可能出问题 | 建议修复 |
| LOW | 代码质量 | 可选修复 |
