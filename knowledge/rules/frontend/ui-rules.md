# 前端 UI 规范（查证清单）

> 提炼自 PCS 前端规范（马诺整理，已去业务化），为跨项目通用规则。
> 触发：任何前端页面 / 组件 / 交互实现时，按对应场景查证本节。
> 红线（违反即不合规）见 `~/.claude/rules/frontend/ui-redlines.md`（自动加载）。

## 表格
- 操作列默认无边框纯文字按钮；无明确业务需求不得加 icon。
- 操作项将换行时，只显示"更多"，全部操作收进下拉菜单，不留外露按钮。
- 普通数据列与操作列支持表头拖拽调宽。
- 查询 / 分页 / 刷新不得重置本次页面会话已调整的列宽。

## 弹窗 / 浮层
- 同级切换必须用 `opened`/`closed` 生命周期事件，禁止 `setTimeout`/轮询猜过渡时长。
- 记录容器链：挂载目标、遮罩归属、z-index、祖先是否有新层叠上下文（overflow/transform/filter）。
- Teleport 到 body 的样式不得依赖"业务根节点作为祖先"的 scoped 后代选择器。

## 反馈闭环（每个用户可触发操作必须完整走通）
- 意图 → 可操作入口 → 即时反馈 → 处理中 → 成功/空/失败 → 恢复或下一步。缺任一环不算通过。
- loading 必须与真实请求绑定：请求开始才显示，成功/空/失败/取消/卸载都必须结束。
- 保存按钮在请求真正开始后进入提交中，防止重复提交。
- 危险操作必须二次确认或提供可撤销窗口。

## 空态 / 错误态
- 空态说明"为什么没有数据" + 用户可执行的下一步操作。
- 错误信息同时给出原因 + 可执行的修复建议 + 重试入口，不能只说"失败"。
- 成功提示说明结果，不使用与实际状态不一致的成功文案。

## 无障碍与键盘
- 主要操作必须键盘可达、可触发；不移除焦点轮廓（除非有 focus-visible 替代）。
- Dialog/Drawer 打开后焦点进入合理位置，关闭后返回触发元素。
- 动态反馈（Toast/校验/异步结果）需让辅助技术感知（`aria-live` 或组件库等价能力）。
- 错误不能只靠颜色表达；仅图标按钮必须有 `aria-label`。

## 性能 / 动画
- 动画只用 `transform` 和 `opacity`；禁止无范围的 `transition: all`。
- 尊重 `prefers-reduced-motion`，非必要动画提供关闭或弱化路径。
- 大列表是否虚拟化按实际数据量与性能证据决定，不以固定阈值擅自加依赖。

## 表单
- 校验即时、错误就地反馈在对应字段附近。
- Placeholder 只作示例/提示，不能替代 Label；Label 层级稳定。
- 表单草稿所有者唯一，父子组件不得互相覆盖真值。

## 视觉验收（提交前）
- 模板属性 / class 对 ≠ 视觉正确，必须核对运行时 computed style。
- 按钮至少覆盖 default/primary/danger/success/warning/link 及 normal/hover/active/focus/disabled/loading。
- 静态检查拿不到 computed style 时标 `not_run`，不得猜测或返回视觉一致结论。

## 深色模式
- 深色主题同步浏览器 `color-scheme`；原生 Select/Input/滚动条保持可读。
- 图片/边框/遮罩/图表在深浅主题下均需验收。
