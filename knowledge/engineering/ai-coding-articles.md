## 1. 腾讯 TAB：从 Vibe Coding 到 Harness（大仓 AI 工程化实战）

- **问题**：AI 独立跑完整产品需求（TAPD→方案→代码→CR→MR）卡在协作/流程/信任，非模型能力。
- **骨架**：SPEC-First（先磨完整设计文档）→ 4 Agent 接力（需求/方案/开发/审查）+ 总控状态机 → 13 阶段接力赛 + 7 门禁脚本 + 5 人工关卡 → MCP 交付闭环。
- **关键机制**：
  - 集成测试前置：开发完成 = 代码 + 单测 + 接口用例 + 接口测试（审查打回 1.8→0.4 次）
  - 门禁基线差集 B−A：只阻断"新增失败"，剥夺 AI"这是历史问题"的解释权
  - 软/硬门禁分级 + 软门禁伤疤：硬=红线即停，软=留警告继续但绕过变得醒目
  - 下游不改上游：需改只提阻塞项（责任边界 > 任何 prompt 调优）
  - 熔断：连续打回 ≥3 次 → 暂停人工介入
  - Team Mode 撞墙 → "复杂度自给自足"陷阱：机制主要在 fix 自己引入的副作用 → 80% 概率删掉
  - 团队规约落仓库，Memory 只放个人偏好
- **已吸收**：SPEC-First（`/design` skill）、熔断、下游不改上游（gates.md）。
- **备选**：基线差集 B−A、软/硬门禁分级。
- **不移植**：TAPD/iWiki/工蜂/企微 5 个 MCP、沙箱 Docker、Playwright 前端冒烟（腾讯基建/Go 大仓）。

## 2. 企业微信 Skill：AI 代码生成率 94%（单任务工程化流水线）⭐ 方法论密度最高

- **问题**：AI 不是不会写代码，是"不会按工程规范开发需求"——上下文塞不下、物料分散、命名不一致、模糊指令越界、验证不闭环、跨会话失忆。
- **骨架**：8 阶段流水线（设计稿→拆解→定位→实现→验证→模拟器验证→沉淀→提交），每阶段输入/产出/退出标准可机器校验 + 4 条公理。
- **关键机制**：
  - 五步定位法（漏斗收敛）：意图消歧→模块定位→脚本 grep→调用链→确认；前 2 步不读代码，第 3 步脚本定位，第 4 步才 Read
  - 三级金字塔知识库：L1 overview <5KB 默认 preload / L2 模块按需 / L3 语义桥；配漂移检测（SHA 基线 + pre-commit 强制维护）
  - 语义二分：**联想用于搜索，引用用于决策**——找代码可大胆联想（5 维矩阵），定交互必须引依据（拦截点清单，禁"看起来像就加"）
  - 公理Ⅱ：判断留给 LLM，数据交给脚本（LLM 最不擅长精确数值和幂等执行）
  - 红线分层：Critical（6 条全流程）/ Standard（30+ 按阶段），YAML 单一真源 + 触发即停固定模板
  - 落盘判定：成功证据 = 落盘文件（git log -1 hash 更新），不靠 stdout
  - A/B/C 验证分类：A 代码 bug 回实现 / B 验证设计错修订计划 / C 脚本时序自修 ≤2 轮；编译自修复上限 3 轮
  - TECH_SPEC.md 跨会话传承（§0 自检/§1 边界/§3 模块地图/§5 不变式/§7 演进）
  - 硬关卡 HK：任何不可逆动作前人工确认
  - 金句："references/ 比 tools/ 体量更大——AI 提效在工程而不在模型"
- **已吸收**：五步定位法（code-access 定位漏斗）、漂移检测（learnings）、落盘判定（verification）、红线分层+触发即停（gates）、语义二分（design+review）、A/B/C 分类（verification）。
- **不移植**：iOS 模拟器验证、Figma 语义桥、TAPD/企微 MCP（行业绑定）。

## 3. 腾讯 Harness 落地规范（团队 SOP + 6 支柱）

- **问题**：团队 AI 编码行为不统一；"交付代码成本接近免费，交付好代码成本依然很高"。
- **骨架**：Harness 6 支柱（上下文/工具/编排/状态/评估/约束恢复）+ 3+1 Phase（Planner→Generator→Evaluator→Archiver）+ AGENTS.md 索引 + 3 阶段实施路线 + harness-audit skill。
- **关键机制**：
  - AGENTS.md ~100 行当目录索引，不巨型（OpenAI 实证"巨型 AGENTS.md"失败）
  - 金句："让各类工具适配规范，而不是靠个人去适配各类工具"（人驱动 AI → AI 自驱动）
  - 评估四层：L1 语法编译/L2 逻辑单测/L3 规范合规/L4 架构人工联合审查
  - 反模式清单：巨型 prompt、跳过审核、Rules 不维护、MCP 过度接入、盲目信任 AI、Chat 历史当文档
  - harness-audit：7 维度打分体检（AGENTS 15%/Rules 20%/Skills 15%/MCP 10%/Plan 15%/工程 15%/Commit 10%）
- **已吸收**：audit 理念标备选；6 支柱框架作决策清单的互补认知模型。
- **不移植**：CodeBuddy/Knot/工蜂/七彩石配置步骤（腾讯平台绑定）。

## 4. Loop Engineering → Graph Engineering（多 Agent 编排理论）

- **问题**：单个 Loop 的结构性缺陷——上下文腐烂、错误级联、工具过载（15-20 个工具选择率陡降）、无控制粒度、可观测性差；加"目标失明"（古德哈特：指标被用力优化后不再测原目标）。
- **骨架**：Graph = (V 节点, E 边, S 状态, P 策略)；三种拓扑（菱形扇出扇入 / 主管-工人 / 流水线）；Anthropic 5 模式。
- **关键机制**：
  - **确定性 > 智能体数量**：Verifier 独立验证节点，用全新干净的眼睛只看结果；模型判断落节点、代码可靠落边上
  - 三把尺子（上下文保护/可并行/专业化）判断何时该多 agent；数据：多 agent 强 90.2% 但 token 15×
  - 工作图快变、角色图慢变：任务拆分可现场灵活，长期权限（谁改 DB/绕过审批）必须慢变可审计
  - 别为了图而图（YAGNI）；现实锚点：测试真跑过、钱真到账
- **已吸收**：三把尺子（dev-workflow 并行前过筛）、工作图/角色图（gates 治理红线）、目标失明（决策清单 #32）。
- **不移植**：LangGraph/AutoGen 框架对比（不搭多 agent 生产系统）。

## 5. AI 原生研发：Vibe → 底座 + 护栏 + 协作

- **问题**：Vibe Coding 适合一次性，做不了"能持续迭代的系统"；缺的不是 AI 能力，是专业开发先搭好的底座。
- **骨架**：三层——基础设施（日志/鉴权/权限/API/定时任务/MCP 标准设施）→ 工程护栏（Rules+Skills+CLI+DB 管控+组件化）→ 协作机制。
- **关键机制**：
  - 渐进哲学："先让 AI Coding 运转起来，再让护栏随需求逐步生长"；"真正 ROI 最高的方式是先转起来"
  - 三层 Rules（AGENTS.md 工程规范 / anydev_rule 流程+用户保护 / Memory 项目约定）；**Rules 保底线不犯错，Skills 提效率干活快**
  - 轻量 SDD：`draft_ → ready_ → done/` 文件名即状态，文档命名约定就是工作流
  - DB 变更风险分级：加字段直接执行 / ALTER 先确认 / 批量先评估影响 / DROP 硬拦截
  - 组件化让审查可行：组件 100-200 行、改动集中、Story 当组件说明书
  - 让 AI 看见问题四层：静态检查反馈 / AGENTS.md 汇总 / dev.sh 自主管理 / Playwright 验证
  - ⚠️ RTK 实测：效果一般、偶发压缩 bug、语义混淆 → 弃用（本机 RTK 的外部数据点）
- **已吸收**：SDD 状态流转（`/design` 方案生命周期）、DB 变更风险分级（sql-best-practices D 节）。
- **不移植**：团队协作层（页面评论提需求、能力地图给非开发者、Anydev 容器——单人 CLI 场景用不上）。

## 6. 老项目上下文工程：让 AI 读懂老项目

- **问题**：历史债务重的项目 AI 常判断出错；"AI 和开发的区别 = 上下文多少"。
- **骨架**：AI 上下文工程——静态上下文（AGENTS.md）→ 动态落盘 → 带着 AI 重构 → 自动化测试工程 → 债务治理常态化。
- **关键机制**：
  - AGENTS.md 只留索引概要（路径 + 1-2 句摘要），细节就近落盘到模块 AGENTS.md，同步更新根索引
  - 知识落盘规范：出现可复用规则/兼容性/排障结论 → 立即落盘（与第 2 篇漂移检测互补）
  - 屎山清理五步：移除死代码 → 做减法（复杂架构简单化）→ 定规范 → 自动化测试 → 债务常态化
  - 金句："落地执行、沟通提效、记录沉淀都可以交给 AI，唯独思考不可以"
- **已吸收**：印证 AGENTS.md 索引规范（knowledge/ 分层已符合）；"AI 提效 = 降低沟通成本"补充北极星理解。
- **不移植**：视觉回归流水线、工蜂 AI 评审规则（需 CI 流水线，偏行业）。
