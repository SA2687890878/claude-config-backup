# 自动迭代机制

> Harness 自身的持续改进回路：用数据驱动迭代，而非拍脑袋。

**版本**：v4.0 | **最后更新**：2026-08-27

---

## 迭代循环

```
Plan（分析现状、定目标） → Do（执行改进） → Check（审查结果、查根因） → Act（更新配置） → 循环
```

---

## 迭代触发条件

### 自动触发

| 条件 | 触发动作 |
|------|---------|
| 工作流执行失败 | 分析失败原因，优化工作流 |
| 审查通过率 < 80% | 分析常见问题，完善审查清单 |
| Agent 调用超时 | 优化 Agent 提示词，简化任务 |
| 用户反馈问题 | 收集反馈，设计改进方案 |

### 手动触发

| 触发词 | 动作 |
|--------|------|
| 优化工作流 | 分析当前工作流，设计改进方案 |
| 改进 Agent | 优化 Agent 角色定义和提示词 |
| 更新文档 | 完善文档和模板 |
| 审计回顾 | 执行周期审计，生成报告 |

---

## 迭代内容

| 对象 | 迭代什么 | 怎么迭代 |
|------|---------|---------|
| 工作流 | 步骤、Agent 角色、触发词映射、输出格式 | 收集执行数据 → 分析问题 → 改进 → 更新文档 → 验证 |
| Agent | 职责定义、提示词、自检清单、输出格式 | 收集数据 → 分析表现 → 优化定义 → 测试 |
| 文档 | 工作流文档、契约模板、审查清单 | 收集反馈 → 分析问题 → 更新 → 验证可用性 |

---

## 迭代最佳实践

1. **小步快跑**：每次只改一个点，快速验证，及时调整
2. **数据驱动**：收集执行数据 → 分析根因 → 基于数据决策
3. **持续改进**：定期回顾，不追求一次性完美
4. **记录沉淀**：记录迭代过程，沉淀经验教训到知识库
5. **用户参与**：收集反馈，纳入迭代计划，验证改进效果

---

## 迭代记录要求

每次迭代在对应产物旁记一条（不必用固定模板）：
`日期 | 改了什么 | 为什么 | 效果如何 | 经验教训`——够可追溯即可，不要为仪式感写空模板。
