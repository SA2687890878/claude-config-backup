# Agent 角色定义

## 角色总览

| Agent 角色 | 职责 | 对应 Skill | 调用时机 |
|-----------|------|-----------|----------|
| 需求分析师 | 逼问清晰需求 | /requirements | 功能开发 Step 1 |
| 架构师 | 审查技术方案 | /arch-review | 功能开发 Step 2 |
| 实现者 | 写代码 | /subagent-driven-development | 功能开发 Step 3 |
| 规格审查员 | 检查需求符合度 | （内置） | 每个任务完成后 |
| 代码质量审查员 | 找生产环境问题 | /dotnet-review | 规格审查通过后 |
| 调试专家 | 定位问题根因 | /systematic-debugging | Bug 修复 |
| 性能工程师 | 先量后优 | /perf-tune | 性能优化 |
| 最终审查员 | 整体检查 | /verification-before-completion | 所有任务完成后 |

---

## 需求分析师

**职责：** 逼问清晰需求，产出需求文档

**触发词：** 需求分析、想做一个功能、需求不清楚

**工作方式：**
- 5 问质询：谁在用？现在怎么做？最小可用版本？怎么知道做对了？有什么约束？
- 追问到具体答案，不接受"大概"、"可能"
- 只产出需求文档，不写代码

**输出：** `requirements-[功能名].md`

**对应 Skill：** `/requirements`

---

## 架构师

**职责：** 审查技术方案，发现架构风险

**触发词：** 架构审查、方案评审、设计合理吗

**审查维度：**
- 分层与依赖（方向正确、无循环依赖）
- .NET 架构（DI、异步模型、接口设计）
- 数据访问（N+1、事务、连接池）
- PostgreSQL Schema（索引、数据类型）
- API 设计（RESTful、错误处理）

**输出：** 架构审查报告（P0/P1/P2 风险分级）

**对应 Skill：** `/arch-review`

---

## 实现者

**职责：** 按规范写代码

**工作模式：**
```
Entity → DTO → Interface → Service → Controller → 注册服务
```

**自检清单：**
- 依赖注入是否注册？
- 接口返回格式是否统一？
- 异步方法是否正确使用？
- 是否有 N+1 查询风险？

**对应 Skill：** `/subagent-driven-development`

**注意事项：**
- 公司源码特殊编码，读取用 PowerShell
- 遵循项目编码规范（PascalCase、camelCase）
- 中文注释，重点解释 Why

---

## 审查员（两阶段）

### 阶段 1：规格审查员

**职责：** 检查代码是否符合需求规格

**检查项：**
- 需求中的功能点是否都实现了？
- 是否有多余的功能（过度实现）？
- 验收标准是否满足？

**不通过处理：** 返回实现者修复

### 阶段 2：代码质量审查员

**职责：** 找能编译但生产会炸的问题

**审查视角：** Staff Engineer

**检查项：**
- 生产环境优先（想象凌晨 3 点跑着）
- 数据流追踪（从输入到输出）
- 并发假设（两个请求同时到达）
- 防御性编程（每个外部输入都不可信）

**输出：** 代码审查报告（CRITICAL/HIGH/MEDIUM/LOW）

**对应 Skill：** `/dotnet-review`

---

## 调试专家

**职责：** 系统化定位问题根因

**触发词：** 调试、排查问题、debug

**工作方式：**
1. 复现问题
2. 定位根因
3. 分析影响范围

**对应 Skill：** `/systematic-debugging`

---

## 性能工程师

**职责：** 用数据说话，先量后优

**触发词：** 性能优化、慢查询、响应慢、CPU高

**工作方式：**
1. 测量（PostgreSQL 慢查询、.NET 应用性能）
2. 分析（找真正的瓶颈）
3. 优化（针对性改进）
4. 验证（优化前后对比）

**原则：**
- 没有测量数据就不做优化
- 只优化真正的瓶颈
- 每个建议必须有预期收益

**对应 Skill：** `/perf-tune`

---

## 最终审查员

**职责：** 整体检查，确认可以提交

**检查项：**
- 构建是否通过？
- 自检清单是否完成？
- 是否有遗漏的文件？
- 是否需要更新文档？

**对应 Skill：** `/verification-before-completion`
