# 完整工作流说明

## 工作流总览

| 工作流 | 触发词 | Agent 数量 | 说明 |
|--------|--------|-----------|------|
| 功能开发 | 开发/添加/实现 | 6 | 完整开发流程 |
| Bug 修复 | 修复/bug/报错/异常 | 3 | 调试专家驱动 |
| 性能优化 | 优化/慢/性能 | 2-3 | 先量后优 |
| 代码审查 | 审查/review/看看代码 | 1-2 | 多视角审查 |
| 会话启动 | 开始/今天做什么/继续 | 1 | 状态检查 |
| 探索讨论 | 讨论/有什么方案/探索 | 1 | 头脑风暴 |
| 跨项目 | 跨项目/联动开发 | N+2 | 并行实现 |

## 工作流 1：功能开发

**触发词：** `开发` / `添加` / `实现` / `做一个功能`

### 流程

```
Agent 1: 需求分析师 (/requirements)
  - 5 问逼出清晰需求
  - 产出 requirements-[功能名].md
  ↓
Agent 2: 架构师 (/arch-review)
  - 审查技术方案
  - 发现 P0/P1/P2 风险
  ↓
Agent 3: 实现者 (/subagent-driven-development)
  - Entity → DTO → Interface → Service → Controller
  - 每个任务完成后自检
  ↓
Agent 4: 规格审查员
  - 检查代码是否符合需求规格
  - 不通过则返回实现者修复
  ↓
Agent 5: 代码质量审查员 (/dotnet-review)
  - Staff Engineer 视角
  - 找能编译但生产会炸的问题
  ↓
Agent 6: 最终审查员 (/verification-before-completion)
  - 构建检查
  - 自检清单
  - 确认可以提交
```

### 输出格式

```
## 完成总结
- **变更文件**: [列表]
- **变更内容**: [一句话描述]
- **注意事项**: [需要特别注意的点]
- **下一步**: [建议的后续动作]
```

## 工作流 2：Bug 修复

**触发词：** `修复` / `bug` / `报错` / `异常` / `出错了`

### 流程

```
Agent 1: 调试专家 (/systematic-debugging)
  - 复现问题
  - 定位根因
  - 分析影响范围
  ↓
Agent 2: 实现者
  - 最小改动原则修复
  - 保持向后兼容
  ↓
Agent 3: 代码质量审查员 (/dotnet-review)
  - 确保修复不引入新问题
  - 检查边界条件
```

---

## 工作流 3：性能优化

**触发词：** `优化` / `慢` / `性能` / `响应慢` / `卡`

### 流程

```
Agent 1: 性能工程师 (/perf-tune)
  - 先量后优，用数据说话
  - PostgreSQL 慢查询分析
  - .NET 应用性能分析
  - 输出测量报告
  ↓
Agent 2: 实现者
  - 根据测量数据针对性优化
  - 不猜测，只优化真正的瓶颈
  ↓
Agent 1: 性能工程师（复测）
  - 优化前后对比
  - 确保无功能退化
  - 量化收益
```

---

## 工作流 4：代码审查

**触发词：** `审查` / `review` / `看看代码` / `检查一下`

### 流程

```
方案/设计审查：
  → 架构师 (/arch-review)

代码变更审查：
  → 代码质量审查员 (/dotnet-review)

并行审查（复杂场景）：
  → 同时调度多个 agent 从不同角度审查
```

---

## 工作流 5：会话启动

**触发词：** `开始` / `今天做什么` / `继续` / `上次做到哪了`

### 流程

```
① 状态检查
   - git status（未提交的改动）
   - git log --oneline -5（最近提交）

② 上下文加载
   - 自动读取记忆系统
   - 加载项目文档索引

③ 任务建议
   - 基于当前状态推荐下一步
   - 提醒未完成的任务
```

---

## 工作流 6：探索讨论

**触发词：** `讨论` / `有什么方案` / `怎么做` / `探索`

### 流程

```
① 头脑风暴 → 调用 /brainstorming
   - 多角度探索方案
   - 列出 pros/cons

② 方案评估
   - 结合项目实际情况
   - 推荐最适合的方案
```

---

## 安全模式

**激活：** `小心操作` / `安全模式` / `/careful`
**关闭：** `取消安全模式` / `不用小心了`

激活后，执行危险操作前会警告：
- `rm -rf` / `git push --force` / `DROP TABLE` 等
- .NET: `dotnet ef database drop`
