# 置信度标注规范

> 配合 `rigor-standards.md` 使用，定义信息来源分级和置信度标注方式。

## 信息来源分级

| 等级 | 定义 | 举例 |
|------|------|------|
| **A** | 官方一手来源 | docs.github.com、官方 changelog、标准文档、源码 |
| **B** | 可靠二手来源 | Wikipedia、知名技术博客、经核实的第三方文档、官方论坛/Stack Overflow 高分回答 |
| **C** | 推理得出 | 无法直接引用，但基于可靠前提和已知事实推导 |
| **D** | 推测/不确定 | 没有直接依据，仅为可能性列举或经验感觉 |

## 输出标注规则

### 事实性结论

在首次给出事实性结论时，在括号内标注来源等级：

> GPT-5.6 Sol 在 Copilot 的专长是「大代码库 agent 工作」[A]
> 这种架构在大型 monorepo 中通常导致构建时间上升[C]

### 不确定场景

| 场景 | 正确做法 |
|------|----------|
| 没有证据 | 说「未找到相关文档」或「当前无可靠数据」 |
| 只能推测 | 说「推测是……，但未确认，因为……」 |
| 存在争议 | 呈现双方论点 + 各自的证据来源等级 |
| 数据可能过时 | 标注最后已知时间 + 建议验证方式 |

### 验证推荐

对于置信度 C/D 的断言，给出可执行的验证方法：

> 推测是 PostgreSQL 15+ 才支持该特性[C]。验证方式：`SELECT current_setting('server_version')` 或查官方 release notes。

## 反模式（禁止）

- ❌ 把推理[ C ] 伪装成事实[ A ]
- ❌ 在不确定时不标注，等用户追问才承认
- ❌ 用「据我所知」代替具体置信度等级——请用 [A]/[B]/[C]/[D]
