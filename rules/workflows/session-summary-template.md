# Session 总结模板

> 借鉴自 COMPASS Skills 的 session 关闭工作流，在对话压缩或结束时结构化总结。

## 什么时候使用

- 对话即将压缩时
- 长会话结束时
- 需要跨会话延续工作时

## 总结内容

### 必须保留

1. **修改文件列表**
   ```
   修改了：
   - path/to/file1.cs (做了什么)
   - path/to/file2.vue (做了什么)
   ```

2. **测试命令和验证结果**
   ```
   测试：
   - 命令: dotnet test
   - 结果: 通过 (X passed, 0 failed)
   ```

3. **关键决策和理由**
   ```
   决策：
   - 选择了方案 A，因为 [理由]
   - 没用方案 B，因为 [理由]
   ```

4. **需求偏差记录**（如果有）
   ```
   偏差：
   - 用户要求 X，但我做了 Y
   - 原因：[为什么]
   - 状态：已向用户确认 / 待确认
   ```

5. **未解决的问题**
   ```
   待解决：
   - [ ] 问题 1：需要用户确认 XXX
   - [ ] 问题 2：需要进一步调查 YYY
   ```

### 可选保留

- 讨论过程中的关键信息
- 临时方案的后续 TODO
- 相关的上下文信息

### 不需要保留

- 完整的对话历史
- 重复的信息
- 已经解决且没有后续影响的问题

## 总结格式

```
## Session 总结 [YYYY-MM-DD]

### 完成的工作
- [任务 1]: [简述]
- [任务 2]: [简述]

### 修改的文件
- file1.cs: [改了什么]
- file2.vue: [改了什么]

### 测试结果
- 命令: [测试命令]
- 结果: [通过/失败]

### 关键决策
- [决策 1]: [理由]
- [决策 2]: [理由]

### 偏差记录（如果有）
- [偏差 1]: [说明]

### 待解决
- [ ] [问题 1]
- [ ] [问题 2]
```
